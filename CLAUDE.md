## High‑Level Architecture

- **`cli_cracker.py`** – Entry‑point script. Uses `argparse` to parse command‑line options and orchestrates the workflow (hash generation, password cracking, PDF cracking). Delegates to the core modules.
- **`cracker.py`** – Implements the *hybrid* cracking strategy for generic hashes: first tries a dictionary attack (`dictionary_utils`) and, if that fails, falls back to a brute‑force attack (`bruteforce_utils`).
- **`bruteforce_utils.py`** – Provides a multiprocessing brute‑force engine. Generates candidate passwords (`generate_candidates`) and distributes work across all CPU cores, reporting progress and statistics.
- **`dictionary_utils.py`** – Simple line‑by‑line dictionary attack supporting MD5, SHA‑256, and bcrypt.
- **`pdf_cracker.py`** – PDF‑specific cracking logic. Supplies three attack modes (dictionary, brute‑force, hybrid) using the same multiprocessing pattern as `bruteforce_utils`. Relies on the `pikepdf` library.
- **`hashing_utils.py`** – Wrapper around `hashlib` (MD5, SHA‑256) and `bcrypt` for hash creation and verification.
- **`test_cracker.py`** – Unit‑test suite covering hashing utilities, candidate generation, dictionary and brute‑force attacks, and the hybrid workflow.
- **`summary.md`, `GEMINI.md`** – Additional documentation generated by external tools; not required for code execution.

### Design Notes
- The codebase follows a *modular* approach: each attack method is isolated in its own module, making it easy to replace or extend (e.g., adding a new hash algorithm).
- Multiprocessing is used throughout the brute‑force components to fully utilize multi‑core CPUs (`os.cpu_count()`).
- All user‑facing commands are funneled through `cli_cracker.py`, keeping the CLI surface consistent.
- Wordlists are plain‑text files; the tools read them line‑by‑line, ignoring empty lines and handling UTF‑8 gracefully.
